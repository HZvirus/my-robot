# 科普对话：话题漂移自动检测

> 本文档总结科普百科（Science）对话中「话题漂移检测」的设计、实现与调参过程。
> 对应代码：apps/ai-service/app/services/science_service.py 与 app/core/config.py
> 前端无需改动：apps/h5-app2/src/stores/science.ts 自动跟随会话 id。

## 一、背景与问题

- ScienceView 科普对话基于 conversationId 维护上下文，历史按时间线性拼接进 prompt。
- 同一会话内连续追问时，模型能记住前文（多轮对话）。
- 问题：用户彻底换话题时（例如从「恐龙灭绝」跳到「三国演义」），旧上下文仍被拼入新回答，污染回答且浪费 token。
- 本质：conversationId 是「会话容器」，不是「话题单元」，需要把两者解耦。

## 二、业界方案对比

| 方案 | 机制 | 缺点 |
| --- | --- | --- |
| 手动新建会话 | 用户点「新对话」 | 依赖用户自觉 |
| 滑动窗口 | 只保留最近 N 条 | 只限长度，不解决话题污染 |
| 自动摘要 | 旧上下文压成摘要 | 细节丢失，旧话题仍可能串味 |
| 话题检测自动换会话 | embedding 相似度或 LLM 分类 | 有误判，需调阈值 |
| 检索式上下文 | 每轮检索相关历史注入 | 实现重（MemGPT 式） |

本项目采用「话题检测自动换会话」（方案 A）：基于 embedding 余弦相似度判定话题漂移，判定后自动开新会话。

## 三、实现（方案 A）

### 3.1 配置项（config.py）

    # Topic-drift detection: cosine similarity below this value starts a fresh conversation.
    SCIENCE_TOPIC_SIM_THRESHOLD: float = 0.51
    SCIENCE_TOPIC_WINDOW: int = 4
    SCIENCE_TOPIC_USER_WEIGHT: float = 0.6
    SCIENCE_TOPIC_DECAY: float = 0.9

### 3.2 核心逻辑（science_service.py）

- _cosine_similarity：余弦相似度计算，向量归一化防除零。
- _load_topic_vector：最近 SCIENCE_TOPIC_WINDOW 条消息的 embedding 加权均值作为话题中心。
  - 用户消息权重 0.6，助手回复权重 0.4（SCIENCE_TOPIC_USER_WEIGHT）
  - 按位置指数衰减 0.9（SCIENCE_TOPIC_DECAY），越新权重越高
- _is_new_topic：新消息与话题中心的余弦相似度低于阈值即判定换话题。
- stream_answer 开头：续聊先做检测，判定换题则生成新 uuid 并清空历史，响应首帧下发新 id。
- 检测异常兜底：except Exception 时保持原会话，聊天永不中断。

### 3.3 数据流

    请求带旧 conversationId
        - 后端加载该会话历史
        - embedding 计算相似度
        - 低于 0.51 时生成新 conversationId 并清空历史
        - 响应首帧下发 data: {"conversationId": "新id"}
        - 前端 store 收到后更新，下一条请求携带新 id


## 四、阈值标定过程（关键）

初始 0.45 与 0.65 均失败，最终 0.51 通过全部用例。

| 阈值 | 失败点 | 原因 |
| --- | --- | --- |
| 0.45 | 西游记相似度 0.4944 未换题 | bge-m3 无关话题相似度偏高（0.40 到 0.49） |
| 0.65 | 相关追问被误杀 | 相关追问区间约 0.53 到 0.64，低于 0.65 |
| 0.51 | 全部用例正确 | 落在相关（0.53 以上）与无关（0.48 以下）的间隙中点 |

实测分布（bge-m3，中文文本）：

| 类别 | 足球话题 | 药物话题 |
| --- | --- | --- |
| 相关追问 | 0.53 ~ 0.62 | 0.53 ~ 0.64 |
| 无关话题 | 0.32 ~ 0.47 | 0.40 ~ 0.48 |

## 五、请求与响应机制（重要认知）

- 第 N 条请求体携带的 conversationId 必然是旧 id：前端发送时无法预知后端会判定换题。
- 换题只体现在响应首帧：data: {"conversationId": "新id"}。
- 前端 store（science.ts）收到首帧新 id 后写入 conversationId，第 N+1 条请求起携带新 id。
- 判断是否生效的正确方法：查看会话列表（GET /api/science/conversations）是否出现多条记录，或查看第 N 条响应的首个 data 事件。

## 六、相似度计算演进

实测对比（同质窗口与混杂窗口）：

- 同质窗口（最近几条全是同一话题）：均值余弦更强（0.6406 对 0.5902），均值相当于集成。
- 混杂窗口（历史夹杂别的话题）：MaxSim（取与每条历史的最大余弦）更稳，可锚定真正相关的那一条。
- 两者都无法解决「回到更早话题」（从台风跳回足球），这是线性窗口方法的共同短板。
- 已落地增强：用户消息加权（见 3.2），抗长助手回复稀释，近期意图优先。


## 七、已知局限

- 线性窗口只能看最近 N 条，无法处理「回到更早话题」。
- 绝对阈值依赖 embedding 模型的相似度分布，更换模型需重新标定。
- 代词式追问（例如「那它怎么形成的」）语义中性，可能偏低被误判为换题。

## 八、后续演进方向

- 方案二：双阈值 + 模糊区 LLM 仲裁（仅边界案例调模型判断，成本可控）。
- 方案三：检索式上下文（MemGPT 式），彻底解耦会话与上下文。
- 相对阈值：sim_recent 与 sim_baseline 的差值，对 embedding 分布不敏感。

## 九、调参与验证

- 观察日志：science topic sim=0.xxx new_topic=...（_is_new_topic 每轮输出）。
- 相关追问被误判（应续聊却换题）：调低 SCIENCE_TOPIC_SIM_THRESHOLD。
- 换题未被识别：调高 SCIENCE_TOPIC_SIM_THRESHOLD。
- SCIENCE_TOPIC_USER_WEIGHT 提高则话题更偏向用户意图；SCIENCE_TOPIC_DECAY 调低则更看重最近一轮。
- 修改后需重启服务：uvicorn app.main:app --reload --port 8000


## 十、面试可能的问题

以下问题覆盖本次设计的核心决策，可作面试自测或讲解提纲。

### 10.1 多轮对话记忆是怎么实现的？

- 后端以 conversationId 为会话键，消息持久化到 Message 表。
- 每轮请求按 conversationId 加载历史，拼成 system + 历史 + 当前消息 再调用 LLM。
- 前端在 SSE 首帧拿到 conversationId，后续请求自动携带。

### 10.2 为什么用 conversationId 管理上下文，而不是前端每次传全部历史？

- 服务端权威管理上下文，历史不依赖前端，刷新页面或换设备不丢失。
- 支持权限校验（ensure_access 判断归属）。
- 避免请求体过大与前端可篡改。

### 10.3 话题漂移检测的原理？

- 用 embedding 把消息变成语义向量，计算余弦相似度。
- 话题中心是最近 N 条消息的加权均值（用户 0.6、助手 0.4，时间衰减 0.9）。
- 新消息与话题中心相似度低于阈值 0.51，判定换题，自动开新会话。

### 10.4 阈值 0.51 怎么来的？

- 0.45 太低：bge-m3 无关话题相似度可达 0.49，换题识别不出。
- 0.65 太高：相关追问只有 0.53 到 0.64，会被误杀。
- 用真实数据测分布，取相关与无关的间隙中点，且做成配置可调。

### 10.5 请求里还是旧 conversationId，是不是没生效？

- 不是。请求必然带旧 id，前端发送时无法预知后端会判定换题。
- 换题体现在响应首帧的 data: {"conversationId": "新id"}。
- 验证方法：看响应首帧，或会话列表是否出现多条记录。

### 10.6 均值向量和 MaxSim 各有什么优劣？

- 同质窗口（最近几条同一话题）：均值更强，等价于集成。
- 混杂窗口（历史夹杂别的话题）：MaxSim 能锚定真正相关的一条。
- 两者都无法处理「回到更早话题」。

### 10.7 为什么做用户消息加权？

- 用户消息代表真实意图，助手长回复会稀释话题方向。
- 时间衰减让最近几轮占主导，符合对话注意力分布。
- 两个参数都可配，调参无需改代码。

### 10.8 异常情况怎么兜底？

- embedding 后端异常时捕获并保持原会话，聊天永不中断。
- 权限异常返回 404，避免会话 id 可被探测。
- 流式中断时仍持久化半截回复并标记 interrupted。

### 10.9 方案有哪些已知局限？

- 线性窗口只能看最近 N 条，无法处理「回到更早话题」。
- 绝对阈值依赖 embedding 模型的相似度分布，换模型需重新标定。
- 代词式追问（「那它怎么形成的」）语义中性，可能被误判为换题。

### 10.10 如果要进一步提高准确率，怎么演进？

- 双阈值 + 模糊区 LLM 仲裁：只在边界案例调用模型判断，成本可控。
- 相对阈值：sim_recent 与 sim_baseline 的差值，对分布不敏感。
- 检索式上下文（MemGPT 式）：不判换题，改为每轮检索相关历史注入，彻底解耦会话与上下文。
